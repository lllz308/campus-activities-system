# 需求与工程意图

## 用户与目标

| 用户 | 目标 |
| --- | --- |
| 学生 | 注册和登录；查看可报名活动；报名或取消报名；查看自己的报名记录 |
| 活动组织教师 | 注册和登录；创建、修改、发布、取消或删除自己组织的活动；了解报名人数 |

## V1.0 功能需求

1. 用户能够以学生或教师身份注册，并使用用户名、密码登录。
2. 未登录用户也能查看已发布且尚未结束的活动。
3. 教师能够创建草稿或已发布活动，并管理自己创建的活动。
4. 学生能够在报名截止前报名已发布且有剩余名额的活动。
5. 学生能够取消自己的报名，并查看自己的报名记录。

## 业务规则

1. 用户名全局唯一，密码不少于 8 位。
2. 报名截止时间早于活动开始时间，结束时间晚于开始时间。
3. 教师只能修改和删除自己组织的活动。
4. 活动已有报名时不能直接删除，可将状态调整为 `CANCELLED`。
5. 同一学生不能重复报名同一活动。
6. 报名人数达到容量、报名截止或活动未发布时拒绝报名。
7. 修改后的容量不得小于当前报名人数。

## 工程意图

### 为什么建设

校园活动信息和报名过程分散，学生难以及时获知活动，教师也缺少统一的发布和管理入口。

### 本轮解决的问题

建立“教师发布活动 - 学生浏览活动 - 学生报名活动”的最小闭环，并确保关键业务规则在服务端执行。

### 重要约束

- V1.0 采用单体分层架构，保持部署简单。
- 使用 REST API，前后端可独立演进。
- 数据访问集中在 Repository，业务规则集中在 Service。
- 不向代码仓库提交真实密码、Token 或生产数据库配置。
- 并发报名时对活动记录加悲观写锁，避免超卖。

### 完成判断

- Maven 构建和自动化测试通过。
- 公开用户能查询活动。
- 教师能完成活动创建和管理。
- 学生能登录、报名、取消报名和查询个人报名。
- 违反角色、时间、容量和重复报名规则时得到明确错误响应。
